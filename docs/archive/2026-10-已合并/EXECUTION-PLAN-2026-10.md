## 〇、战略一句话

> **OracleMind = 概率层（Probability Layer）+ 记分板（Scoreboard）**
> 让预测变成一种**可携带的能力**——它在自有产品里好玩（玩法层），在别人的产品里可用（协议层），而每一次被使用都在让它变准（内核层）。
> 商业预测是最上层的变现场景，**不是第二条产品线**。

## 三、战略框架（回顾，详见设计提案）

```
玩法层（有趣）→ 协议层（无处不在）→ 内核层（可信）
     ↑                                        ↓
     └──────── 样本飞轮：更多样本 → 更准 → 更有价值 ──┘
```

- **玩法层**：事件预测 / 个人遗嘱 / 元预测 / 条件链 / AI 辩论 / 对决 → 产出参与·样本·社区
- **协议层**：MCP / A2A / OpenAPI / Widget / 浏览器插件 / Discord Bot → 产出分发·生态·跨场景样本
- **内核层**：10 Agent 共识 / 共形预测 / 校准层 / Brier / 推理图谱 → 产出**带校准证书的概率**
- **商业层**（叠加在协议层之上）：商业事件预测 + 事件×数值融合 → 产出收入与行业可信度

## 四、依赖图：什么必须先做

```
┌─ BLOCKER 0：部署通道 ────────────────→ 一切（不通则所有改动不可见）
├─ BLOCKER 1：Prediction 加 probability ─→ 所有概率玩法（概率演化/校准/解剖）
├─ BLOCKER 2：LLM fallback ────────────→ 引擎可靠性（转型后 AI 概率是玩法要素）
└─ BLOCKER 3：首页冷启动 7.33s ────────→ 体验基线

阶段 1（转飞轮）
  概率演化追踪 ──依赖──→ B1
  预测解剖 ──────依赖──→ 结算样本（需先有量）
  Certified Probability API ──依赖──→ B2 + 校准层（已有）

阶段 2（无处不在）
  浏览器插件 / Widget / MCP ──依赖──→ Certified Probability API

阶段 3（商业与壁垒）
  L1 商业事件语料 ──依赖──→ 无（可独立启动）
  L3 事件×数值融合 ──依赖──→ 校准声誉（建议后于阶段 1）
```

> **顺序原则**：先修阻断 → 再建玩法（攒样本与声誉）→ 同时铺协议（分发）→ 后上商业（变现）。
> **理由**：商业层 L3 的说服力依赖"你的校准值得信任"这一声誉，而声誉来自样本与社区。**顺序错了，商业层卖不动。**
