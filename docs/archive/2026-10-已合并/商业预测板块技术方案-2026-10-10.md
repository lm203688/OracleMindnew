# 商业预测板块：要不要做、怎么做

> 日期：2026-10-10 ｜ 类型：**技术方案建议（待 owner 决策）**
> 问题：是否基于现有基础 + 最新预测推演技术，补齐"商业预测"这个大板块？
> 结论先行：**做，但绝不能做成"商业预测软件"。要做的是「商业决策的概率层」——站在时序基础模型之上，而不是去和它们竞争。**

---

## 一、结论：做，但要用一个精准的切面

| 选项 | 判断 | 理由 |
|---|---|---|
| ❌ 做通用商业预测软件（需求预测 / 销量预测 / FP&A） | **不做** | 技术栈完全不同 + 红海 + 需要接客户数据 + 会把项目变成企业软件公司 |
| ❌ 自建时序预测模型 | **不做** | 2026 已有更强的开源预训练模型，自建是重造轮子 |
| ✅ **做「商业事件预测」** | **强烈建议** | 你现在就能做，且几乎无人竞争 |
| ✅ **做「校准增强」的数值预测** | **建议** | 接开源 TSFM，你只做校准层，成本极低、差异化极强 |
| ✅ **做「事件 × 数值融合」** | **强烈建议（这是真正的创新点）** | 全球无人做，且完美复用你现有全部资产 |

## 二、为什么不能直接做"商业数值预测"

### 2.1 技术栈是完全不同的两套东西

| | OracleMind 现有 | 商业数值预测主流 |
|---|---|---|
| 预测对象 | **离散事件**（X 会不会发生） | **连续数值**（下季度销量多少） |
| 方法 | 多 Agent 共识 + 共形预测 + 校准 | ARIMA/ETS/Prophet → **时序基础模型** |
| 输入 | 事件陈述 + 检索 + 推理 | 历史时间序列 + 协变量 |
| 输出 | 概率 + 置信区间 | 点预测 + 预测区间 |
| 数据 | 无需客户数据 | **需要客户历史数据** |

### 2.2 竞争已是红海

企业需求预测在 2026 已有大量成熟玩家（Prediko、Perimattic 等一众需求规划软件），且所有 ERP / 云厂商自带模块。**在"销量预测"这一格硬碰没有胜算。**

## 三、关键发现：时序基础模型社区正在喊"我们需要校准"

我查了 2026 年时序基础模型（TSFM）的生产实践现状：

**已经商品化的部分**（Amazon Chronos-2 / Google TimesFM / Salesforce MOIRAI-2）：
- **Zero-shot**，无需训练、无需特征工程、无需 per-SKU 建模
- 冷启动问题基本消失（两周新 SKU 立即出预测）
- 单 GPU 每秒数百条预测
- → **"点预测"这件事，已经被开源模型免费解决了。自己再做一遍毫无意义。**

**它们的局限（这就是你的机会）**：

| 行业原话 | 含义 |
|---|---|
| *"Uncertainty is the deliverable, **not the point forecast**"* | 决策是**针对区间**做的，不是针对均值 |
| *"a confident wrong number is **worse than an honest wide one**"* | 自信的错误比诚实的宽区间更糟 |
| *"evaluate probabilistic quality — **calibration of the prediction intervals**"* | 必须评估**预测区间的校准** |
| *"'Point forecasts only' is an **anti-pattern**"* | 只给点预测被明确列为反模式 |
| *"Covariates are where your domain knowledge goes"* | 模型不知道你的促销日历、价格、行业事件 |
| *"Hard business constraints are **not learned**"* | 业务约束不会被模型学到 |

> **整个时序预测行业在 2026 年的核心痛点，恰恰是「校准」——而这是 OracleMind 已经建好的能力（共形预测 327 行 + 校准层 + Brier/ECE/可靠性分解）。**

**战略结论**：
```
不要做时序基础模型的竞争者，做它们的「概率校准层 + 事件推理层」。
它们免费给你点预测，你负责让它变得可信、可解释、可决策。
```

## 四、三层技术路线

### Level 1：商业事件预测 —— 现在就能做，零新技术

**做什么**：把现有事件预测能力平移到商业语境。

| 商业事件类型 | 例子 | 谁需要 |
|---|---|---|
| 竞品动作 | 竞品会不会在 Q4 前降价？ | 战略 / 定价 |
| 监管与合规 | 这项法规会不会通过？何时生效？ | 法务 / 风控 / 政府事务 |
| 供应链风险 | 供应商会不会违约 / 断供？ | 采购 / 供应链 |
| 交易与并购 | 这笔并购会不会完成？ | 投研 / BD |
| 技术采用 | 这个标准的采用率会不会在 2027 前超过 30%？ | 产品 / 研发 |
| 宏观与行业 | 利率路径、行业拐点 | 财务 / 战略 |

**为什么这是你的地盘**：
- ✅ 这些是**离散事件**，正是 OracleMind 的形态（不是时序）
- ✅ **可验证**（有明确结局 → 可算 Brier → 符合 Precision Over Hype）
- ✅ **竞品真空**：Gartner 做定性分析（无概率、无记分板）；预测市场做公共事件（不做企业事件）；**没人做"企业专属事件概率"**
- ✅ 现有资产可直接复用：多 Agent 共识、共形预测、校准层、`event-corpus`（54 条已验证事件）

**需要补的**（都很轻）：
- 商业事件语料（从财报电话会、SEC filing、行业新闻、专利/招标数据构建）
- 领域 Agent（供应链 / 监管 / 竞品 / 宏观）
- `domain` 字段扩展（现有 politics/tech/crypto 等需加 business/regulatory/supply-chain）

### Level 2：校准增强的数值预测 —— 接开源 TSFM，只做校准层

**做什么**：客户给一段历史序列 → 你调开源 TSFM 拿点预测 → **你输出共形校准后的区间**。

```
客户历史序列 ──→ Chronos-2 / TimesFM（开源，自部署）──→ 点预测 + 原始区间
                                                          ↓
                                            OracleMind 共形预测层（已有 327 行）
                                                          ↓
                                    校准后的区间（有覆盖率数学保证）+ 校准证书
```

**差异化**：共形预测给的是**数学上可证明的覆盖率**（"这个区间在 90% 的情况下会覆盖真值"），而不是模型自己拍的方差。这正好回应行业痛点 *"calibration of the prediction intervals"*。

**成本极低**：不训练模型，只做后处理。Chronos / TimesFM 均开源可自部署。

### Level 3：事件 × 数值融合 —— 真正的创新点，全球无人做

**这是我最想给你的建议。** 前两层别人也能做，这一层只有你能做。

**核心思想**：数值预测的天敌是**前提假设崩塌**。传统 TSFM 只会延续历史模式，它不知道"供应商可能断供"这种**离散事件**。

**把离散事件的概率注入数值预测** —— 输出长这样：

```
问题：预测 Q1 产品销量

── Level 2 基线 ─────────────────────────────
12,000 台  ·  共形校准区间 [9,600 – 14,800]（覆盖率保证 90%）

── Level 3 前提事件分解 ─────────────────────
├─ 供应商 A 不断供            82%   → 若失败，销量 -18%
├─ 竞品不在 Q1 前降价         71%   → 若发生，销量 -12%
├─ 新法规 Q1 前不生效         93%   → 若生效，销量 -30%
└─ 渠道 B 按时上架            88%   → 若延迟，销量 -8%

── 条件情景分布 ─────────────────────────────
· 全部顺利      52%   →  13,500
· 竞品降价      24%   →  11,900
· 供应商断供     15%   →   9,800
· 最坏组合       2%   →   7,200

── 建议动作 ────────────────────────────────
最脆弱的假设是「新法规不生效」（93%）：影响 -30% 但概率低 → 建议监控 + 预案
```

**为什么没人能做这个**：它需要同时具备**四样东西**，而市面上没有任何产品同时有：

| 需要的能力 | OracleMind | 时序工具 | Gartner 类咨询 | 预测市场 |
|---|---|---|---|---|
| 时序数值预测 | 需接 TSFM | ✅ | ❌ | ❌ |
| 离散事件概率 | ✅ 已有 | ❌ | ❌（定性） | ✅（仅公共事件） |
| 推理图谱 / 情景合成 | ✅ `scenario-synthesizer` 20.8KB | ❌ | 人工 | ❌ |
| 概率校准 + 共形区间 | ✅ 已有 | 部分（多为未校准方差） | ❌ | ❌ |

**可复用资产（几乎不用重写）**：

| 资产 | 位置 | 状态 |
|---|---|---|
| 情景合成 | `src/lib/engines/scenario-synthesizer.ts` 20.8KB | ✅ 现成 |
| 因果推理 | `src/lib/engines/causal-reasoning.ts` 14.8KB | ✅ 现成 |
| 共形预测 | `src/lib/engines/conformal-prediction.ts` 327 行 | ✅ 现成 |
| 校准层 | `src/lib/engines/calibration.ts` 92 行 | ✅ 现成 |
| 推理图谱 | `GraphNode` / `GraphEdge` + `event-graph-builder` | ✅ 现成 |
| 仿真引擎 | `simulation-engine.ts` 13KB | ✅ 现成 |
| WhatIf 分支 | `WhatIfBranch` 模型 | ✅ 现成 |

> **Level 3 几乎是把你已有的积木重新拼一次，而不是新建。这是它性价比最高的原因。**

## 六、商业意义：这个板块解决了你的一个结构性矛盾

你说了"不以盈利为目的"。但项目要持续运行就需要资源。**商业预测是唯一能同时满足这两点的板块**：

| | C 端玩法 | **B 端商业预测** |
|---|---|---|
| 收费 | ❌ 免费 | ✅ 可以收费 |
| 数据污染 | 需保护校准纯度 | **不污染 C 端数据**（完全独立） |
| 客单价 | — | 高（企业预算） |
| 与"概率层"定位 | 提供样本与社区 | 提供收入与行业可信度 |

> **结论：商业预测板块可以成为"不向 C 端收费"这一决策的财务支撑。**
> 它让你能坚持 C 端的数据纯度，同时不必依赖风投或自掏腰包。

## 七、风险与边界（必须守住）

| 风险 | 对策 |
|---|---|
| 🔴 **变成企业软件公司**（接数据、ETL、权限、SOC2） | **不托管客户数据**。做成 API / Widget，客户自己调；或只接受客户主动输入的上下文 |
| 🔴 与"游戏化/协议化"主线抢资源 | 商业预测 = **协议层的一个垂直场景**，不是第二条产品线。共用内核，不做独立产品 |
| 🟡 商业事件结局难以自动获取 | 优先做**有公开结局**的事件类型（财报、监管、IPO、并购），避开需要内部数据的 |
| 🟡 准度宣称风险 | 每个数字附 `n_resolved` + CI；**样本不足时禁止宣称优于基线**（这是 CORE-GOALS 已有红线） |
| 🟡 GPU 服务成本（TSFM） | 批处理 + 只在 Level 2/3 场景使用；Level 1 完全不需要 GPU |

## 八、建议路线图

| 阶段 | 动作 | 验收 |
|---|---|---|
| **B0** | `Prediction` 表加 `probability` 等字段（所有预测能力的前置） | 概率可持久化 |
| **B1** | **商业事件语料 v1**（公开结局优先：财报超预期 / 监管通过 / IPO / 并购完成） | ≥100 条带真值商业事件 |
| **B2** | 4 个领域 Agent（供应链 / 监管 / 竞品 / 宏观） | 分域 Brier 可算 |
| **B3** | `/business` 商业事件板（复用 arena 骨架） | 首个商业事件预测产生 |
| **B4** | **Level 2**：接 Chronos-2 / TimesFM，共形校准扩展到连续值 | 数值预测输出有覆盖率保证的区间 |
| **B5** | **Level 3**：事件 × 数值融合（情景分布 + 前提分解） | 产出首个完整决策报告样例 |
| **B6** | B 端定价与 API Key（与 C 端完全隔离） | 首笔 B 端收入 |

## 九、需要你决策

| # | 问题 | 我的倾向 |

| 1 | 商业预测做到哪一层？ | **建议 Level 1 + Level 3**，Level 2 可延后（Level 3 的样例价值 > Level 2 的完整性） |
