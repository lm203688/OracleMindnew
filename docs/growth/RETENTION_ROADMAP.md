# OracleMind 留存路线图 · Retention Roadmap

**最后更新**：2026-10-15  
**负责人视角**：产品 / 增长 / 合规  
**核心命题**：OracleMind 现在已经有「概率场引擎 + 日记 + 竞技场 + 校准闭环」，系统侧健康度良好，但**缺真实用户**。留存路线图不追求功能堆叠，只解决一个真问题：**让一个第一次来的外国人，愿意第二天回来，第七天还回来，第十天愿意再付费**。

---

## 0. 一句话结论

> **OracleMind 不是「算命工具」，是「概率场引擎 + 长期校准闭环」。**
>
> 留存的真正杠杆不是更多页面，而是**把「推演 → 预测 → 记录 → 回看 → 复盘」这条闭环，做得像健身记录一样上瘾**。

当前最大的风险不是技术，是：**我们不知道用户到底会不会回来**。所以本路线图分两段：先做**数据基建**，再做**产品干预**。

---

## 1. 现状诊断（截至 2026-10-15）

### 1.1 系统侧已有的留存钩子

| 模块 | 路径 | 留存价值 | 当前状态 |
|---|---|---|---|
| 日记 | `/api/journal` | 用户每日事件沉淀 | 后端存在，无前端入口 |
| 竞技场 | `/api/arena` | 用户主动做预测，形成行为钩子 | 后端存在，无前端入口 |
| 校准闭环 | `/loop` | 把历史预测和验证状态聚合 | API 可用 |
| 反馈 | `/api/feedback` | 收集用户主观反馈 | 未系统使用 |
| 预测精度回补 | `prediction-accuracy` | 证明产品真的在校准 | Brier 0.159 / 9 verified |
| 校准 cron | 07:30 UTC | 自动把过去预测标成对/错 | 已上线 |

### 1.2 当前核心矛盾

- **技术债已收敛**，但**用户数据仍稀薄**。
- **闭环已经跑通**，但**没有前端把闭环展示给用户**。
- **预测精度已经积累**，但**没有用户知道自己正在参与校准**。
- **留存依赖「用户主动预测」，但没有强钩子把用户逼回来**。

**结论**：先不要做新功能，先把「用户为什么来、什么时候回、回来看什么」弄清楚。

## 2. 留存目标（可量化）

### 2.1 北极星指标

**7 日留存率（D7 retention）**

定义：注册用户后 7 天内再次访问并产生一次核心行为（日记/预测/复盘任一）的用户比例。

### 2.2 辅助指标

| 指标 | 目标（3 个月内） | 说明 |
|---|---:|---|
| D1 留存 | ≥ 30% | 用户第二天愿意回来 |
| D7 留存 | ≥ 12% | 一周内至少回一次 |
| 每 7 日核心行为次数 | ≥ 3 | 预测/日记/复盘 |
| 付费转化率 | ≥ 2% | 首次付费用户 / 注册用户 |
| 7 日校准反馈率 | ≥ 15% | 用户确认过预测结果 |

### 2.3 为什么是这套指标

- **D1/D7** 是用户是否真的黏住的最直接证据。
- **核心行为次数** 用来排除「打开一次就走」。
- **校准反馈率** 是我们最核心的差异化，因为 OracleMind 的护城河不是单次日命，而是**用户参与系统校准**。

## 3. 数据层先行（不做基建，不碰产品）

在写任何新功能前，先把留存数据链路补全。

### 3.1 必须补齐的埋点

| 事件 | 说明 | 优先级 |
|---|---|---|
| `signup_completed` | 注册完成 | P0 |
| `daily_forecast_opened` | 打开日预测 | P0 |
| `journal_submitted` | 提交日记 | P0 |
| `arena_prediction_submitted` | 提交竞技场预测 | P0 |
| `prediction_verified` | 预测被验证 | P0 |
| `calibration_page_viewed` | 查看校准页 | P1 |
| `payment_completed` | 支付成功 | P0 |

### 3.2 必须补的表结构

- 在 `user` 表增加 `registered_at` / `last_seen_at` / `cohort_day`
- 在 `prediction` 表增加 `created_at` / `verified_at` / `was_correct`
- 在 `journal` 表增加 `created_at` / `linked_prediction_id`（可选）
- 新建 `retention_metrics` 汇总表（每日刷新）

### 3.3 必须出的看板

一个只读的留存看板，包含：

1. 当日新注册
2. D1 / D3 / D7 留存曲线
3. 用户行为漏斗
4. 付费转化
5. 校准反馈率

**原则**：看板先做，产品后做。**没有看板，后续所有 A/B 都没有意义。**

## 4. 用户漏斗与流失诊断

### 4.1 注册漏斗

```
访问首页 → 了解产品 → 注册 → 首次日预测 → 首次日记/预测 → 再次回来
```

**最可能的断裂点**：

1. 首页承诺和实际体验不一致。
2. 注册后不知道下一步做什么。
3. 用户看完一次结果就走。
4. 没有强提醒把用户拉回来。

### 4.2 流失后常见原因

| 类型 | 特征 | 解法 |
|---|---|---|
| 浅层用户 | 只看一次日预测就走 | 更强的「明日再看」钩子 |
| 日记用户 | 只写日记，不预测 | 把日记和预测连接 |
| 预测用户 | 只看预测，不验证 | 自动验证 + 提醒反馈 |
| 付费犹豫用户 | 试用后不下单 | 更清晰的付费价值叙事 |

## 5. 产品路线图（4 阶段）

### Phase 1 · 0–2 周：补齐前端闭环入口

**目标**：把已经存在但没有入口的后端能力开放出来。

- 给 `/journal` 和 `/arena` 做最简前端
- 在 `/daily-forecast` 里加「今天写一条日记 / 做一个预测」的入口
- 在 `/loop` 里加一个只读「我过去 7 天的校准记录」卡片
- 给 `/api/feedback` 做最小可用入口

**验收标准**：

- 用户从首页进入后，10 分钟内能完成 1 次日记 + 1 次预测 + 1 次回看
- 不需要额外引导文案也能完成

**不做的事**：

- 不重写后端
- 不新增复杂社交功能
- 不做积分商城

---

### Phase 2 · 3–6 周：把闭环做成「用户看得见的成长」

**目标**：让用户意识到自己不是在看一个算命结果，而是在训练自己的概率场。

- 在个人主页加「校准面板」
  - 我做过多少预测
  - 验证了多少条
  - Brier 分是多少
  - 最近 7 天准确率
- 给日记加「情绪 / 事件」结构化标签
- 给预测加「到期提醒」
  - 例如：这条预测 48 小时后到期，请确认结果
- 把用户自己的历史校准数据做成可回看曲线

**验收标准**：

- 用户能看到自己的预测历史
- 7 日内至少 1 次预测被验证的用户占比 ≥ 15%

---

### Phase 3 · 7–10 周：设计留存钩子

**目标**：把用户从「偶尔看一次」变成「习惯回来」。

#### 3.1 每日微钩子

- 每天早上给注册用户一条「今日一问」
- 问题只问一件事，不做长篇
- 例子：
  - 「今天你更愿意投资，还是防守？」
  - 「你今天最重要的一个关系会怎么变？」
  - 「你会把今天的风险归因于环境，还是选择？」

#### 3.2 周复盘钩子

- 每周给用户发一份 **weekly calibration brief**
- 内容不是玄学总结，而是：
  - 你这周预测了哪些事
  - 哪些对了，哪些错了
  - 哪类判断你最容易误判
  - 下周你可以关注什么

#### 3.3 连续行为钩子

- 连续 3 天记录日记，解锁一个「周复盘」
- 连续 5 条预测验证，解锁「个人校准曲线」
- 这些钩子**只给内容，不给积分**

**验收标准**：

- D7 留存较基线提升 ≥ 20%
- 用户回访动机从「看结果」变成「看趋势」

---

### Phase 4 · 11–16 周：把留存做成商业闭环

**目标**：让留存带来付费，而不是靠促销。

#### 4.1 付费触发点

- 不是「看完一次首页就收费」
- 而是：
  - 当你想回看自己的校准历史 → 付费
  - 当你想看更长的预测轨迹 → 付费
  - 当你想看跨周期的校准曲线 → 付费

#### 4.2 付费叙事

- 免费版：单日/单次推演
- 付费版：
  - 历史校准
  - 7 日 / 30 日复盘
  - 预测验证提醒
  - 更完整的能量场演化记录

#### 4.3 定价原则

- 不追高
- 先验证付费意愿
- 再谈规模化

**验收标准**：

- 首次付费率 ≥ 2%
- 付费用户 D7 留存高于免费用户

## 6. 内容与技术配合点

### 6.1 内容层要避免什么

- 不要再用「算命」「八字」「占卜」这类外部话术
- 不要让用户把 OracleMind 理解成一次性玄学工具
- 不要把「预测」写成「命运定论」

### 6.2 应该强调什么

- 概率场
- 推演
- 校准
- 验证
- 回看
- 周期
- 能量基调

### 6.3 文案模板方向

> You are not reading fate.  
> You are training a field.

这句话适合作为产品叙事核心。

---

## 7. 不做什么（重要）

以下事情**不做**：

- 不做积分商城
- 不做社群排行榜
- 不做聊天机器人陪伴
- 不做真人导师
- 不做每日推送轰炸
- 不做无差异化的每日推送邮件
- 不做过度复杂的个人化画像

**原则**：OracleMind 的护城河是**个人校准数据**，不是热闹。

---

## 8. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 数据稀疏 | 当前校准数据量仍不够 | 先做埋点和看板 |
| 用户只看一次 | 首页吸引力不足 | 把入口做成强钩子 |
| 内容过于技术化 | 外国用户理解成本高 | 文案先做产品化 |
| 付费意愿不明 | 现在还不知道谁会付费 | 先用留存数据找付费信号 |
| 合规敏感 | 不能过度承诺预测 | 统一使用概率场话术 |

---

## 9. 建议的优先级

1. **先做留存看板**（没有这个，后面都是猜）
2. **再补 /journal 和 /arena 前端入口**
3. **再做周复盘**
4. **最后做付费分层**

---

## 10. 一句话给团队

> **不要先做更多功能，先做更多被看见的成长。**

如果用户看不到自己的校准历史，他就不会回来。  
如果用户看不到自己的判断正在变化，他就不会付费。
