# OracleMind 五维全面提升报告

> 日期：2026-10-22｜评估维度：全面性 / 实用性 / 使用性 / 互动性 / 前沿性
> 方法：直接扫描 `vercel-deploy/` 生产代码（30 个页面、60+ API、40 个引擎）、schema、实验产物与 Git 历史；结合 2026 年公开技术趋势与市场数据。
> 结论口径：**只评"用户能感知到的产品"，不评"代码里写了但没接通的模块"。**

---

## 一、执行摘要

**综合评分：6.8 / 10（有强内核，但产品定位与体验尚未收敛）**

| 维度 | 评分 | 一句话判断 |
|---|---|---|
| 全面性 | 8.5 | 功能极全（30 页/60+ API/40 引擎），但已出现"功能蔓延"，用户认知负荷高 |
| 实用性 | 6.5 | 有真实决策价值，但"玄学定位"封顶可信度，且自研方法在自有实验里未胜出 |
| 使用性 | 6.5 | 三层入口（30 秒/2 分/5 分）设计聪明，但暗色强制、移动端与无障碍有硬伤 |
| 互动性 | 5.5 | 有竞技场/排行榜/连续记录/分享，但基本是"单机+异步"，缺实时与社交关系 |
| 前沿性 | 7.5 | 技术栈与方法前沿（共形预测/多智能体/A2A/MCP/OpenTimestamps），但竞品已在公开榜霸榜 |

**核心战略判断（一句话）**：
> OracleMind 真正稀缺的资产不是"AI + 玄学"（这个赛道拥挤且可信度封顶），而是**"可公开验证、可校准、防篡改的预测信任层"**。建议走**双轨战略**：玄学做消费级流量与现金流，可验证预测 API/公开榜单做可信度与技术壁垒。

**三个必须立刻纠正的事实**：
1. 自有对比实验（n=305）里，**经验贝叶斯 Brier=0.155，输给 Platt 的 0.140**；ECE 0.115 也略逊 Platt 的 0.091。**不能对外宣称"我们的校准最好"**。
2. 该实验的 raw 概率是**模拟生成**（0.5 中心+弱信号+噪声），不是真实引擎输出——只能算"方法管线跑通"，不能算"模型有效"的论文证据。
3. 产品页自己写着"概率反映的是多视角一致度，不是事件真实可能性"——这句话在诚实上值得肯定，但**同时消解了产品的实用价值主张**，必须重新设计表述。

## 三、五维深度评估

### 3.1 全面性 —— 8.5 / 10（强，但过载）

**亮点**
- 覆盖面罕见：从个人决策、事件推演、风水方位、星盘生肖、合盘共振，到竞技场、日记、公开准确率、质量演化、自评、OracleCore、支付、推荐、分享、导出、Widget、MCP/A2A。
- 工程闭环意识强：预测 → 日记 → 回填 → 校准飞轮 → 公开评分卡，链路是完整的。
- 多语言 + 多支付 + 归因 + 自动化巡检，具备"能运营"的底子。

**短板**
- **功能蔓延**：30 个页面里，`ai-future / domains / loop / preview / visual-resonance / tuivan-chart / widget / resonance/pair` 等页面与主路径关系弱，分散注意力、拉高维护成本。
- **信息架构缺失**：没有一个清晰的"产品地图"。新用户从落地页进入后，不知道竞技场、日记、准确率页各自解决什么问题。
- **命名不统一**：`tuivan`（推演）、`resonance`、`oracle-core`、`quality-evolution` 混用中英与概念，用户难理解。

**提升动作（P0）**
1. 画一张产品信息架构（IA）图，把 30 页收敛为 **3 条主旅程**：`快速预测` / `深度决策` / `竞技与验证`；其余页面归入"实验室"折叠区。
2. 首页增加"能力导航"：预测 / 竞技 / 我的战绩 / 公开准确率，四个入口一目了然。
3. 对 90 天无流量页面做埋点审计，合并或下线（`ai-future`、`tuivan-chart` 优先评估）。

---

### 3.2 实用性 —— 6.5 / 10（有真价值，但被定位拖累）

**亮点**
- 三层深度（30 秒快速 / 2 分钟个人 / 5 分钟深度多智能体交叉验证）符合真实使用节奏。
- 输出是"结论 + 情景 + 时机 + 行动项"，不是空泛的运势文案——这是相对玄学 App 的实质优势。
- 竞技场用真实已决事件结算 Brier，公开评分卡可查，具备"可验证"的稀缺属性。

**短板**
1. **可信度封顶**："古代推演 + 概率"的叙事，让严肃用户第一反应是"玄学"，让科研用户第一反应是"不严谨"。
2. **自研方法未胜出**：n=305 实验中 Platt 优于经验贝叶斯（Brier 0.140 vs 0.155）。若继续宣传"独家校准确准"，是自伤。
3. **实用价值主张自相矛盾**：结果页写明"概率不是真实可能性"——那用户为什么要为决策付费？
4. **B 端能力被埋没**：已有 `/api/mcp`、`/api/openapi.json`、A2A Agent Card，但没有"开发者/企业"入口与定价，浪费了最可能变现的资产。

**提升动作（P0）**
1. **重写价值主张**：从"预测准不准"改为"**帮你在不确定中做更稳的决策，并全程可验证**"。卖"决策质量 + 可审计"，不卖"神准"。
2. **诚实呈现方法对比**：公开页展示 Platt / Isotonic / 经验贝叶斯 的 Brier/ECE 对比（含本项目未胜出的事实），反而建立信任。学术与商业都吃这一套。
3. **把 raw 概率换成真实引擎输出**：当前实验用模拟 p，必须接 `prediction-engine` 真实输出重跑，否则论文与产品都站不住。
4. **开放 Pro/API 层**：基于现有 MCP/OpenAPI 做"预测即服务"（按调用计费），面向量化、内容、研究团队。

---

### 3.3 使用性 —— 6.5 / 10（入口聪明，细节粗糙）

**亮点**
- 游客自动登录、免费额度可见、结果页漏斗埋点（`result_render`/`upgrade_click`）——转化意识专业。
- 重型模块用 `next/dynamic + ssr:false` 拆分，首屏优化做过。
- 付费墙放在"最想要的瞬间"（看到结果后），并明确列出"锁了什么"，比抽象升级页好。

**短板**
1. **暗色强制**：结果页/配置页大量硬编码 `oklch(0.06…)` 深色背景，不跟随系统主题，浅色用户与低视力用户不友好。
2. **无障碍（a11y）风险**：大量低对比度灰字（如 `oklch(0.55)` on `0.06`），未见到 WCAG 对比度校验。
3. **移动端未验证**：网格 `grid-cols-4/8`、固定 max-width，未做移动端断点审计；玄学/预测类产品移动端占比通常 >80%。
4. **付费摩擦**：$4.99 单次 + $9.99 订阅双按钮并列，首次用户决策成本高；且未提供"先看 1 段免费完整解读"的渐进解锁。
5. **引导缺失**：没有 onboarding，用户不知道"深度模式要填生辰/地点""竞技场怎么玩"。

**提升动作（P0/P1）**
1. 主题化：把硬编码 `oklch` 收敛为 CSS 变量 + `next-themes`，支持浅/深/跟随系统；跑一遍对比度检查。
2. 移动端优先：375px / 768px 两档断点全页面走查；表单改单列；结果页大数字适配。
3. 渐进解锁：免费用户可看"1 段完整解读 + 其余模糊"，比直接锁 6 个卡片转化更高。
4. 加 3 步 onboarding（这是什么 / 怎么问 / 怎么看结果），首次进入触发。
5. 性能：Lighthouse 跑 LCP/CLS/INP，目标移动端 LCP < 2.5s。

---

### 3.4 互动性 —— 5.5 / 10（有骨架，缺"人味"）

**亮点**
- 竞技场（市场/提交/排行榜/结算）、日记回填、连续记录（streak）、分享页、推荐归因、有用性反馈——互动要素其实不少。
- 竞技场用真实结局结算，天然具备"比拼"的公平基础。

**短板**
1. **单机感强**：排行榜是异步静态榜单，没有实时对战、没有好友、没有关注、没有评论。
2. **没有社交图谱**：Co-Star 的核心粘性来自"加好友看合盘"；OracleMind 有合盘页却没有好友关系链。
3. **没有通知/召回**：预测到期、排行榜变化、好友超越，均无推送或站内信。
4. **UGC 缺失**：用户不能发起自己的预测题目，内容全靠系统供给。

**提升动作（P1）**
1. **实时竞技场**：按周/按事件开"联赛"，实时更新排名，结算日直播式榜单。
2. **社交图谱**：好友/关注 + "好友预测对比" + 合盘分享（复用现有 `compatibility`）。
3. **通知系统**：预测到期提醒、排名变动、好友超越、周报。
4. **UGC 题目市场**：用户出题 → 他人下注 → 系统结算，形成内容飞轮。
5. **共创预测**：多人对同一问题各自给概率，聚合展示"群体 vs 你的分歧"。

---

### 3.5 前沿性 —— 7.5 / 10（技术真前沿，但战场已变）

**亮点**
- 方法栈是真前沿：Split Conformal（有限样本覆盖保证）、经验贝叶斯收缩、Murphy 分解、ECE/LogLoss/BSS、特征显著性、多智能体网格、镜像概率场、数据流算子、OpenTimestamps 防篡改。
- 工程栈新：Next 16 / React 19 / Prisma 6 / Tailwind 4。
- 协议前沿：MCP + A2A Agent Card + OpenAPI，具备"被其他 Agent 调用"的潜力。
- 已有 305 条真实事件回填集 + 对比实验产物，科研管线不是空谈。

**短板**
1. **战场已变**：2026 年 AI 预测 Agent 已在公开榜厮杀——FutureSearch 在 Metaculus FutureEval 排 #2/284、ForecastBench #5/427，并在 Metaculus Cup Summer 2026 击败 681/683 名人类预测者；Mantic 在 Metaculus Cup Fall '25 进前 1%。OracleMind 尚未上任何公开榜。
2. **实验证据弱**：raw 概率是模拟的，且自研方法未胜出（见 3.2）。
3. **前沿方法未产品化**：共形预测目前主要是"诊断工具"，没变成用户能看懂的"预测区间/把握度"。
4. **数据实时性不足**：缺 GDELT/新闻/市场数据的实时接入，预测仍偏"离线推演"。

**提升动作（P0/P1）**
1. **上公开榜**：把引擎接入 ForecastBench / Metaculus FutureEval，拿到可公开引用的排名——这是最强的前沿性背书。
2. **共形预测产品化**：把 `splitConformalPrediction` 的输出变成用户可见的"90% 把握区间"，而不是藏在 API 里。
3. **实时数据层**：接入 GDELT / 新闻 / 市场价格流，做 retrieval-augmented 预测。
4. **Agent 生态**：把 MCP/A2A 做成"可被第三方 Agent 调用"的预测服务，抢占 agent 经济入口。
5. **真实引擎重跑实验**：用真实 p 替换模拟 p，重跑 4 校准器对比，并如实报告结果。

## 四、2026 技术与市场趋势（决定"往哪走"）

| 趋势 | 2026 公开数据点 | 对 OracleMind 的含义 |
|---|---|---|
| **预测市场主流化** | 2026 年 2 月 Polymarket+Kalshi 合计交易量约 **187 亿美元**；ICE（纽交所母公司）2025 年 10 月投资 Polymarket；2026 中期选举进一步推高 | 预测"可信度/校准"成为刚需；OracleMind 的评分卡与防篡改是差异化 |
| **AI 预测 Agent 军备竞赛** | FutureSearch：Metaculus FutureEval #2/284、ForecastBench #5/427、击败 681/683 人类；Mantic 进 Metaculus Cup 前 1% | 必须上公开榜，否则"前沿"无从证明 |
| **多智能体编排成企业标配** | Gartner 预测 2026 年底 **40% 企业软件将嵌入 AI Agent**；多 Agent 编排是年度主趋势 | OracleMind 的 Agent Mesh + MCP/A2A 可切 B 端"预测 Agent" |
| **共形预测进入主流学术** | ICLR 2026 有共形预测专题（如 COMPASS 医学分割），不确定性量化成决策刚需 | 项目已有实现，应产品化为"把握区间" |
| **玄学/情绪消费巨大** | Co-Star 约 **430 万 MAU**、累计下载 2000 万+；2026 年被 Midjourney 收购 | 消费级流量与留存有真实市场，但需情绪价值而非"科学"包装 |
| **超个性化 + 透明化** | CES 2026 主题为 AI 驱动超个性化；用户要求"哪些是人、哪些是 AI"透明 | 结果页应标注"AI 视角/古典视角/数据来源"，透明即信任 |

**市场需求的三个真实痛点**（OracleMind 可切）：
1. **信息过载下的决策焦虑** → 要"一个数 + 为什么 + 怎么办"，不要长篇玄学。
2. **对 AI 预测的不信任** → 要"可验证、可回溯、不篡改"，这正是 commit-seal + 公开评分卡。
3. **孤独感与意义感** → 玄学/星盘提供情绪价值，是天然入口，但必须与"决策工具"分层。

## 五、竞品定位矩阵

| 玩家 | 定位 | 强项 | 软肋 | OracleMind 的差异点 |
|---|---|---|---|---|
| **FutureSearch / Mantic** | AI 预测 Agent | 公开榜排名高、纯预测 | 无消费级情绪价值、无玄学入口 | 有消费级入口 + 可验证资产 |
| **Metaculus / Manifold** | 群体预测平台 | 社区、题库、校准 | 无个人化、无 AI 推演体验 | 个人化 + 多智能体 |
| **Polymarket / Kalshi** | 预测市场交易 | 资金、流动性、监管 | 纯金融、无决策解读 | 决策解读 + 校准评分 |
| **Co-Star / 测测** | 玄学/星盘消费 | 情绪价值、社交、留存 | 无预测校准、无可验证性 | 有真实结算与评分卡 |
| **通用 LLM（GPT/Claude）** | 通用问答 | 泛化强 | 无校准、无留痕、无防篡改 | 专用校准 + 前瞻注册 |

**定位结论**：OracleMind 不应与 FutureSearch 比"纯预测排名"，也不应与 Co-Star 比"玄学娱乐"。它的空位是——
> **"消费级入口 + 科研级可验证性"的中间层**：让普通人用情绪友好的方式提问，但给出可审计、可回溯、可校准的答案。

## 六、战略建议：双轨制

```
┌─────────────────────────────────────────────────────────┐
│  A 轨：消费级（现金流 / 流量）                            │
│  玄学·星盘·合盘·每日运势 → 情绪价值 → 订阅/单次付费        │
│  目标：留存、分享、低成本获客                              │
└───────────────────────┬─────────────────────────────────┘
                        │ 共用同一套"预测 + 校准 + 验证"内核
┌───────────────────────▼─────────────────────────────────┐
│  B 轨：可信预测层（壁垒 / B 端）                          │
│  公开评分卡 + 防篡改注册 + MCP/A2A API + ForecastBench 排名│
│  目标：可信度背书、开发者/企业付费、被其他 Agent 调用       │
└─────────────────────────────────────────────────────────┘
```

**为什么必须双轨**：
- 只做 A 轨 → 沦为玄学 App，可信度封顶，无法证明"前沿"。
- 只做 B 轨 → 没有流量与现金流，且要与 FutureSearch 正面硬拼。
- 双轨共用内核 → 边际成本低，且 A 轨的情绪数据反哺 B 轨的校准样本。

## 七、提升路线图（按投入产出排序）

### P0（0–4 周，立刻做，决定生死）

| # | 动作 | 具体落点 | 验收 |

| P0-1 | **真实引擎重跑校准实验** | 用 `prediction-engine` 真实 p 替换 `experiments/conformal-coldstart.mjs` 里的模拟 p | 新结果 JSON 的 `notes` 不再出现"模拟"；4 校准器 Brier/ECE 可复现 |
| P0-2 | **诚实重写价值主张** | 首页 hero + 结果页文案：卖"决策质量+可验证"，不卖"神准" | A/B 测试点击率；移除"概率非真实可能性"的自伤表述，改为"这是我们基于 X 条证据的校准估计，历史 Brier=…" |

## 八、指标体系（North Star + 护栏）

**North Star**：`周有效决策数`（用户完成一次预测并回填/采纳的比例 × 周活）

| 层级 | 指标 | 目标 |
|---|---|---|
| 获客 | 落地页→首次预测转化率 | > 25% |
| 激活 | 首次预测完成率 | > 60% |
| 留存 | D7 / D30 留存 | > 20% / > 8% |
| 变现 | 结果页付费转化率 | > 3% |
| 可信 | 公开评分卡 verified 数 / BSS | verified > 100；BSS > 0 |
| 互动 | 竞技场周参与率 | > 15% |
| 体验 | 移动端 LCP / 错误率 | < 2.5s / < 1% |

**护栏指标（红线）**：
- BSS < 0（差于气候态基线）→ 停止一切"准确"宣传，先修模型。
- 公开榜排名缺失 → 不得对外称"前沿/领先"。
- 模拟概率进入任何对外数字 → 立即下架。

## 九、风险与红线

1. **科学诚信风险**：模拟 p 的实验结果不得作为"模型有效"证据；自研方法未胜出必须如实披露。
2. **定位风险**：玄学叙事过重会永久封顶 B 端与科研合作；建议品牌分层（消费品牌 vs 预测 API 品牌）。
3. **合规风险**：若涉预测市场/下注，需明确"非博彩"边界与地区合规（Kalshi 受 CFTC 监管，Polymarket 有地区限制）。
4. **数据风险**：回填集必须保留 `source` 与 `resolvedAt`，论文与产品数字都要能追溯到公开主源。
5. **过度扩张风险**：30 页已是上限，新增功能前必须先下线一个。

## 十、一句话总结

> OracleMind 已经"什么都有"，现在缺的是"**让用户一眼看懂它凭什么值得信**"。
> 把 30 个页面收敛成 3 条旅程，把"玄学"降为入口、把"可验证预测"提为主角，用公开榜和真实实验证明自己——**这是从 6.8 分走向 8.5 分的最短路径。**
