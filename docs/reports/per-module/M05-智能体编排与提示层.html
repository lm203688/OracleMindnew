板块 5 · 智能体编排与提示层

边界：science-layer.ts + agent-factory.ts + react-reasoner.ts + agent-mesh.ts + agent-memory.ts + modern-deep-analysis.ts（2766 行）+ inference-loop.ts + pipeline.ts；API：/api/oracle-core/*、/api/self-eval、/api/agent-trace。

一、流程合理性 / 走通性 / 人类使用习惯

流程链路：pipeline 编排 → modern-deep-analysis（LLM 多步深析，2766 行最大模块）→ react-reasoner（ReAct 循环）→ agent-mesh（多智能体）→ science-layer 注入校准上下文到 Agent 提示。

走通性 / 风险：

  • 校准注入已修复（2026-10-14 确认）：science-layer 优先读 db.predictionFeedback 真实样本（断链 #6 已修），getHistoricalAccuracyContext 真实生效。
  • 过度工程风险：modern-deep-analysis 单文件 2766 行 + agent-mesh 多智能体 → token/成本/延迟三高；对"给一个概率"的产品，多智能体可能杀鸡用牛刀。
  • circuit-breaker（324 行）已存在，可做成本护栏，但需确认是否真正拦截 runaway。
  • /api/agent-trace 存在，透明化"思考过程"是信任资产，但默认可能过冗。

人类使用习惯：用户要快答案 + 可解释；多智能体慢且贵，且长链推理易让用户等不及。透明（trace）好，但需"摘要优先、详情可展开"。

结论：校准注入 8/10，工程克制 4/10，成本护栏 5/10，透明度 7/10。

二、市场竞品与需求比较

框架 定位 关系
LangGraph 状态图编排（生产级） OracleMind 自研 pipeline 可迁移以降低维护
CrewAI 角色化多智能体 agent-mesh 思路类似，但自建
AutoGen（微软 1.0 GA） 对话式多智能体 生态成熟
Anthropic/OpenAI Agent SDK 原生 SDK 轻量首选

需求：预测产品不需要重型多智能体；市场趋势是"框架收敛 + 轻量 SDK"。自研可逆，但维护成本高。

三、最新开源技术融合机会

  • LangGraph：把 pipeline 改为状态图，获得 checkpoint/回溯/可观测，降低自研维护。
  • Anthropic/OpenAI Agent SDK：轻量替代 agent-mesh，省 token。
  • circuit-breaker（已有） 接成本计量，设每预测 token 上限。
  • Agent 可观测：把 /api/agent-trace 做成前端"推理时间线"组件。

四、单板块提升方案

  • P1-①：用 LangGraph 重写 pipeline，保留 modern-deep-analysis 作为节点，获得可观测与回放。
  • P1-②：给 modern-deep-analysis + agent-mesh 加 token/成本预算，circuit-breaker 强制拦截。
  • P1-③：trace 默认出"一句话摘要 + 可展开推理时间线"，平衡透明与速度。
  • P2：评估是否把 agent-mesh 简化为单 Agent + 工具调用（多数预测场景足够）。
