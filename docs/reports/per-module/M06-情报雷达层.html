边界：lib/intelligence/*（prediction-market.ts 175 行 + intelligence-calibrator.ts）+ automation/expansion-chains.ts + marketing-chains.ts + tech-radar-ledger.ts + api/intelligence-gather + api/automation/weekly-scan + api/tech-radar/improvement-ledger。

一、流程合理性 / 走通性 / 人类使用习惯

流程链路：prediction-market.ts 拉 Manifold 免 key 共识 → intelligence-calibrator 融合 → weekly-scan cron 产出 docs/intelligence-reports → tech-radar-ledger 跟踪技术演进。

走通性 / 风险（设计最干净之一）：

  • prediction-market.ts 是教科书级实现：免 key、9s 超时、流动性加权置信、关键词匹配缩放融合权重（防弱相关硬拽）、失败一律 found:false 优雅降级——工程纪律极佳。
  • 单一来源局限：只接 Manifold（英文市场），中文事件/国内议题覆盖几乎为 0；weekly-scan 产出是静态 md，未结构化进可检索层。
  • 情报层是后端，用户侧价值未释放：预测 UI 没把"市场共识锚点"显式呈现，用户看不到"为什么这个值"。

人类使用习惯：用户要"这预测有依据吗"——情报锚点是信任证明，但需以"依据卡片"形式进主 UI，而非藏在报告里。

结论：工程实现 9/10，覆盖广度 3/10，用户可见度 3/10。

二、市场竞品与需求比较

竞品 定位 关系
AlphaSense 企业级市场/竞争情报（Forrester 领导者） 昂贵，OracleMind 角度=预测锚定情报，垂直差异
Similarweb / Crayon 数字/竞争情报 流量数据，非事件共识
GDELT / EventRegistry 开源全球事件流 可补齐多源

需求：预测类产品用户要"可验证依据"；通用 CI 工具贵且不贴预测。OracleMind 的"预测接地情报"是空白定位，但单源 + 不可见削弱价值。

三、最新开源技术融合机会

  • GDELT / EventRegistry：实时多语事件流，补齐 Manifold 单一英文源，中文覆盖。
  • Firecrawl / Crawl4AI：定向抓取权威源做 RAG 摘要。
  • Ollama 本地摘要：敏感/离线情报本地化，降成本。
  • GraphRAG（见 M03）：情报与古典/事件图谱统一检索。

四、单板块提升方案

  • P1-①：接 GDELT/EventRegistry 做第二/三情报源，中文事件至少一条本地源。
  • P1-②：把共识锚点做成预测 UI 的"依据卡片"（含市场链接 + 偏离度）。
  • P1-③：weekly-scan 输出结构化（JSON + 向量），进检索层而非仅静态 md。
  • P2：情报置信度与校准层联动——低共识时主动下调可声明置信。
