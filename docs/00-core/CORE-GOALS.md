## 一、一句话定位

**OracleMind 是一个「可验证概率预测的公共计量 / 决策基础设施」——用中国古代哲学框架提供结构假设，用现代数据科学提供可验证的测量，产出**可被第三方检验**的事件概率预测与个人倾向推演。**

> **定位升级（v1.2，落实用户 11-04 决策）：** OracleMind 从「概率场实验室」升维为 **公共计量 / 决策基础设施（Public Measurement & Decision Infrastructure）**——类比 Meter 之于电量、Bureau 之于标准计量，**信任 = 第一资产，验证落地 = 最高杠杆**。它不生产"神秘答案"，而是生产**可复现、可审计、带信用背书**的概率计量与验证体系，供第三方独立检验。这一升维是 11-04 用户裁决与专项讨论群六方共识的落点（详见 §三 原则与 §十二 合规承诺）。

> **定位升级（v1.1，落实 D1）：OracleMind = 概率层（Probability Layer）+ 记分板（Scoreboard）。** 类比 Stripe = 支付层、Twilio = 通信层——**卖的不是预测，是「带信用背书的概率」（Certified Probability）。** 裸 LLM 只给数字，OracleMind 给带校准证书、共形区间、前瞻性封存 ID 的数字。稀缺性已从「谁能给概率」迁移到「① 人的参与与私有信息 ② 人机混合的增量 ③ 可被信任的长期记分板」，而引擎内核正是那套脚手架。

核心隐喻：**实验室（Virtual Laboratory）**——在没有时空约束的条件下模拟现实实验。

| 实验室要素 | OracleMind 对应物 |
|---|---|
| 实验台 substrate | 五本古籍（渊海子平 / 子平真诠 / 三命通会 / 滴天髓 / 穷通宝鉴）提供结构假设与推理语法 |
| 测量仪器 | 现代推演引擎：10 Agent 共识、蒙特卡洛、共形预测、Brier 校准 |
| 实验记录 | Simulation / WhatIf / Scenario / Graph 节点，全部可持久化、可重放 |
| 实验室笔记本 | **累积的「预测 + 已验证结局」数据集**——长期护城河 |

## 二、双轨产品结构

OracleMind 有两条轨道，职责严格分离，**不可混淆**：

| 维度 | **事件轨（旗舰）** | **个人轨（品牌叙事层）** |
|---|---|---|
| 定位 | **可验证的旗舰产品** | 留存与叙事的品牌层 |
| 主驱动 | 现代情报 + 集成 + 校准 | 古典 substrate（四柱 → 子平倾向场） |
| 输入 | 事件陈述 + 域/区/时域/分辨率标准 | 生辰（birth datetime） |
| 时间锚 | 事件起点 → 时间相位共振（中性 framing） | 生辰四柱 |
| 验证 | **饱满**：resolved outcome ∈ {0,1} → Brier | 饥饿：无 ground truth |
| 可否 claim 准度 | ✅ **可以**（有 Brier / BSS / 方向准确率） | ❌ **不可以**（只能作概率倾向，不宣称准确率） |
| 合规风险 | 低（= 决策支持 / 概率演化分析） | 中（须严防算命话术） |
| 变现路径 | API 订阅 / 按次 / B 端（研究·媒体·投研） | $4.99 Deep 一次性 + Premium 订阅（C 端） |

**铁律：对外一切「准度宣称」只能出自事件轨。个人轨的输出必须始终表述为倾向指数 + 置信区间，永不出现命中率/准确率字样。**

## 三、三大不可协商原则

### 1. Automation First
平台在初次配置后，无需日常人工干预即可运行、改进、增长。定时任务负责运维、情报采集、自我优化与用户触达。

> **落地判据：** 存在一条「监控者被监控」的心跳，且该心跳**不依赖站点自身流量**。任一自动化链 >36h 未跑 → 自动重放 + 告警。

### 2. Precision Over Hype
每一个输出都必须可验证。古代方法提供哲学结构，现代方法提供数据锚定；二者单独都不足够，**融合并交叉验证后的产物才是产品**。

> **落地判据：** 每一个准度数字必须附带**样本量 + 置信区间**。样本量不足时，禁止对外宣称优于基线。

### 3. Validation as Monetization（v1.1 由「Monetization as Validation」更名）
**先验证、再变现**：被第三方持续验证的资产（校准后验、活体记分板、可复现的概率证书）才是定价权来源；变现是验证的自然结果，而非前置条件。Money 不得污染校准数据纯度——核心玩法（事件追踪 / 校准训练 / 概率演化）永久免费、无付费墙阻断，否则样本被刷分与保守化污染，护城河地基自毁。

> **落地判据：** 北极星 = **质量优先 + 基准相对**（v1.2，取代 v1.1 的 WAF×人均已结算——用户 11-04 决策 B）。主分数 = **基准相对 Brier 技能分数（BSS vs 气候学/随机）**，仅统计**已验证结局**题目；参与度（WAF/样本量）作为**独立护栏**，不参与加权、不稀释质量。校准数据是唯一护城河，引入金钱会让玩家变保守、刷分、回避难题，**故以「已验证结局的真实样本量 + 相对基准的质量分数」作为核心先行指标**。B 端 API / 深度解读可付费（见 §二 事件轨变现路径），但 C 端核心玩法不收费。

## 六、北极星指标与验收标准

**北极星（v1.2）：质量优先 + 基准相对**　*（取代原 WAF×人均已结算；用户 11-04 决策 B——质量优先，参与度作为独立护栏不参与加权、不稀释质量。详见 §三 原则三与 §十二 合规承诺）*

> **北极星指标（v1.2 定义）**：主分数 = **基准相对 Brier 技能分数（BSS）**，参照 **气候学（climatology）与随机（random）** 双基准，仅统计已验证结局题目。`north-star.ts`（`_v: 'northstar-b-v1'`）：`NORTH_STAR_MIN_VERIFIED=10` / `NORTH_STAR_MIN_RELIABLE=5`；样本量低于门槛 → `not_reliable`（护栏未达不可判定）。参与度（WAF / 24h 预测数）为独立护栏，不进入质量加权。

| 指标 | 定义（v1.2） | 说明 |
|---|---|---|
| 质量分（主） | BSS vs climatology / random | 相对基准技能分数，仅已验证结局；>0 = 优于基准 |
| 护栏（参与度） | WAF × 人均已结算预测数 | 独立护栏，不参与加权、不稀释质量；未达护栏 → 判定不可靠 |
| 兼容指标 | Brier / ECE / 方向准确率 / 覆盖率 | 保留展示，但主判定以 BSS 为准 |

| 阶段 | 先行指标 | 基线（2026-10-13） | 30 天目标 | 90 天目标 |
|---|---|---|---|---|
| 信任 | 公开已验证事件数 | 54（仅后端） | 150（扩产后公开可见） | 300+ |
| 信任 | Brier / ECE | 0.136 / 0.250 | 0.15 / <0.15 | <0.15 / <0.10 |
| **活跃** | **24h 预测数** | **0（系统空转）** | **>50（最关键先行指标）** | 持续 >200 |
| **活跃** | **事件账本条目** | **空** | 有真实条目 | 持续增长 |
| 活跃 | 周活跃预测者（WAF） | ~0 | 埋点后定基线 | +200% |
| 反馈 | 月回报数 / 真人试玩 | 0 / 0 | 50 / 20 人玩≥3天 | 300 / 持续 |
| 生态 | 第三方 API 调用方 | 0 | 1（B 端付费） | 10 |
| 收入（B 端，非核心） | API / 深度解读 MRR | $0 | 首笔 | $300+ |

### 评分规则理论来源（O1 落地，v1.2）

> 本项目的核心记分体系（Brier 分数、Murphy 分解、经验贝叶斯收缩）以以下理论为溯源，与 Tetlock / Superforecast 并列作为方法学依据：

| 理论 | 引用 | 本项目对应实现 |
|---|---|---|
| Brier 分数（严格适度评分规则） | Brier (1950)；理论溯源：Zenodo 10.5281/zenodo.23764997《概率判断、Brier 分数校准与群体智慧统计理论》(2026-10-29) | `scientific-metrics.ts`（avgBrier / Murphy 分解） |
| Murphy 分解（Brier = Reliability − Resolution + Uncertainty） | Murphy (1973) | `scientific-metrics.ts`（L82 注释）/ `uncertainty-decomposition.ts`（Φ-6 bin-based） |
| 经验贝叶斯收缩 | 经验贝叶斯方法（Zenodo 10.5281/zenodo.23764997） | `calibration.ts`（shrink = sampleSize/(sampleSize+K)，sampleSize=0 → 0.5，绝不伪造精度） |
| 校准微训练（15 分钟 RCT，296 参与者） | Zenodo 10.5281/zenodo.23764997 | 未来教学候选，暂不落地（记录在案，见 docs/reports/oraclemind-intel-fusion-O1-eval-2026-11-06.md） |

**严格适度（strictly proper）评分规则声明**：本项目评分采用严格适度评分规则（Brier 分数），诚实概率可最小化期望损失——如实报告信念即最优策略，无激励偏差。

## 七、数据策略

### 采集
- 预测问题与结局（用于准度追踪）——**核心资产**
- 用户验证反馈（准 / 部分准 / 不准）
- 使用模式（哪些功能被用、哪些被忽略）
- 用户档案（生辰数据，需同意）
- 反馈与功能请求

### 不采集
- 与预测精度或产品改进无直接关系的任何数据
- 无明确用户同意的第三方数据

### 数据即核心资产
累积的「预测 + 验证」数据集是平台的长期首要资产，它支撑：
- **准度校准**（知道哪类方法对哪类问题有效）
- **个性化**（回访用户获得更准结果）
- **竞争壁垒**（无人可复制数年的已验证结局）

## 九、技术演进策略

平台**不依赖裸 LLM 能力**，而是通过以下方式构建智能：

- **Agent 架构设计**：多 Agent 辩论、交叉验证、融合
- **自演进 prompt 优化**：A/B 测试 prompt，测量准度
- **专业能力模块**：领域专属推理链
- **MCP 工具编排**：外部数据源、计算器、数据库
- **零幻觉强制**：每一个论断必须有可追溯来源
- **评测机制**：用户验证反馈闭环 + 前瞻性注册 + 抗污染活体记分板

## 十二、合规承诺（v1.2 新增，用户 11-04 确认）

> 本节把 11-04 用户裁决的四项合规落地**固化为对外承诺**，与代码实现（`financial-scope.ts` / `payment-mode.ts` / `north-star.ts`）一一对应。

| 承诺 | 代码实现（单点裁决） | 验收 |
|---|---|---|
| **① 金融类语料不面向用户** | `financial-scope.ts`：`FINANCIAL_CATEGORIES = {crypto, economics}`，消费端（arena / 公开评分 / forecast 校准 / self-eval）一律 `isFinancialScope` 排除；内部回测保留全量 | 金融事件消费端 grep=0；事件 ID 含 crypto/economics 类别不出现于公开面 |
