## 二、战略定位

### 2.1 一句话

> **OracleMind = 概率层（Probability Layer）+ 记分板（Scoreboard）**
> 类比：Stripe = 支付层，Twilio = 通信层。
> 让预测变成一种**可携带的能力**——在自有产品里好玩，在别人的产品里可用，每一次被使用都在让它变准。

### 2.2 方向澄清（两处，重要）

| 常见误解 | 正解 |
|---|---|
| ❌ "转型做成预测游戏" | ✅ **游戏化**：预测内核不变，双轨定位不变，只是加一层参与机制 |
| ❌ "面向海外就不用管合规" | ✅ 中国体彩规则不适用，但换成 **CFTC 监管**（更硬，详见 §六） |

### 2.3 三层架构 + 样本飞轮

```
玩法层（有趣）→ 协议层（无处不在）→ 内核层（可信）
     ↑                                        ↓
     └────── 样本飞轮：更多样本 → 更准 → 更有价值 ──┘
```

| 层 | 内容 | 产出 |
|---|---|---|
| **玩法层** | 事件预测 / 个人遗嘱 / 元预测 / 条件链 / AI 辩论 / 对决 | 参与 · 样本 · 社区 |
| **协议层** | MCP / A2A / OpenAPI / Widget / 浏览器插件 / Discord Bot | 分发 · 生态 · 跨场景样本 |
| **内核层** | 10 Agent 共识 / 共形预测 / 校准层 / Brier / 推理图谱 / **情报层（见 §5.6）** | **带校准证书的概率** |
| **商业层**（叠加于协议层） | 商业事件预测 + 事件×数值融合 | 收入 · 行业可信度 |

**只做玩法层 = 又一个 Manifold；只做协议层 = 没灵魂的 API；只做内核层 = 现状（Brier 0.136 躺在数据库里）。三层缺一，飞轮不转。**

### 2.4 为什么必须转向"人"

**ForecastBench 官方数据（2026-10-09 当日，Brier Index：50=无信息，100=完美）：**

| 榜单 | 主体 | 分数 |
|---|---|---|
| Tournament（带工具/多智能体） | Top AI（DeepMind） | **69.0** |
| | **超级预测者中位数** | **68.6** |
| Baseline（裸模型无工具） | 超级预测者中位数 | 67.6 |
| | 公众中位数 | 62.5 |
| | 最佳裸模型（kimi-k3/o3/claude/gpt-5.5） | 60.7–61.9 |

**结论**：带工具的 AI 已追平并微超人类顶级预测者（官方"Supers > Forecaster?"列全为 No）。**"AI 给一个概率"正在急速商品化。**
裸模型仍明显落后 → 差距不在模型，在**脚手架**（检索、集成、校准、多智能体辩论）——**而你的引擎正是那个脚手架**（Brier 0.136 落在同一区间）。

→ 稀缺性从"谁能给概率"迁移到：**① 人的参与与私有信息 ② 人机混合的增量 ③ 可被信任的长期记分板**。

## 三、产品设计

### 3.1 玩法矩阵：你现在只占 1 格

| 维度 | 已占 | 可拓展 |
|---|---|---|
| 预测**什么** | 公共事件 | 个人事件、他人行为、**集体判断（元预测）**、**AI 的行为**、自己的过去 |
| 怎么**预测** | 二元、概率 | 数值区间、排序、时点、**条件链** |
| 和谁**玩** | 独处 | vs AI、1v1 对决、组队、群体 |

3 × 6 × 5 = **90 格设计空间**，建议首批只做深 5–6 格。

### 3.2 最值得先做的三个（含可复用资产）

**① 概率演化追踪**（⭐ 首选）
同一事件在 T-30/T-7/T-1 三次预测，画出**信念更新曲线**。
→ 超级预测者与普通人的真正差距不是"猜得准"，是**愿不愿意随新信息更新信念**。这是唯一能直接测量并训练该能力的机制。
→ **当前障碍**：业务接线未做，无法追踪同一用户同一事件的多轮预测。

**② 嵌入式预测**
浏览器插件：选中网页任意一句话 → 右键"预测这件事" → 封存 → 到期自动回探。Discord Bot 同理。
→ **一次性解决"可玩性"与"更多样本"两个诉求**，且完全符合"接入任何场景"。
→ 复用：MCP(1.3KB) + OpenAPI(5.7KB) + embed.js(2KB) 骨架已有。

**③ 预测解剖 Autopsy**
结算后不止给分，而是指出你推理链的哪一步错了（过度自信 / 基础率忽视 / 时间跨度误判 / 跟随羊群）。
→ Metaculus 和 Manifold **都只给分数不给诊断**。
→ 复用：`causal-reasoning`(14.8KB) + `reflection-engine`(12.4KB) 现成。

### 3.3 其他候选（按 ROI）

| # | 玩法 | 可复用 | 难度 |
|---|---|---|---|
| 4 | 个人预测遗嘱（哈希封存+到期复盘） | `commitHash` 已有 | 低 |
| 5 | 条件预测链（"如果 A 那么 B"） | `scenario-synthesizer` 20.8KB + GraphNode | 中 |
| 6 | AI 陪练辩论 | `agent-factory` + `self-consistency` | 中 |
| 7 | 年度回顾 Wrapped | Prediction 表 + 战绩 | 低 |
| 8 | 元预测（预测"人群会预测多少"） | arena 已有 `probability` 人群值 | 低 |
| 9 | 1v1 对决 / 10 赛季制 | 需房间机制 / `arena-score` cron 已有 | 中/低 |

### 3.4 可玩性与成瘾性：设计原则

**用良性成瘾四要素**（自我决定理论）：

| 要素 | 机制 |
|---|---|
| 胜任感 | 校准曲线可视化进步 —— 不是"分数涨了"，是"我变准了" |
| 好奇心缺口 | 结算时刻的自然不确定性（真实的可变奖励，比人工设计的强） |
| 社交承诺 | 组队、对决、公开承诺 |
| 叙事 | 年度回顾、预测图鉴、"我的预测史" |

🚫 **明确禁用（写进产品宪法）**：无限滚动、虚假紧迫感、FOMO 制造、损失厌恶操纵（streak 断裂只重置不断崖）、付费墙阻断核心玩法。
**理由**：① Precision Over Hype 原则 ② 操纵会让玩家为保 streak 而保守作答，**直接污染校准数据** ③ 目标用户是高智识人群，能识别并鄙视。

### 3.5 核心计分：校准误差（ECE），不是猜对率

> 说 70% 的人应该在 10 次里**正好对 7 次**。全对说明他其实该说 95%，也是"不准"。

**校准是难度无关的**——全选 90% 的题，正确率很高但没信息；ECE 不会被这种取巧污染。这是它优于猜对率的科学理由。**没有任何竞品把校准曲线做成游戏主界面。**

## 四、协议化：把预测变成可携带的能力

### 4.1 核心产品：Certified Probability（带校准证书的概率）

```jsonc
// POST /api/forecast → Response  ← ✅ 已上线（509eec86，api/forecast/route.ts 156 行）
{
  "probability": 0.34,
  "ci95": [0.22, 0.47],
  "calibration_certificate": {            // ← 裸 LLM 给不了这个
    "brier": 0.136, "ece": 0.06, "n_resolved": 847,
    "domain_brier": { "tech": 0.140, "politics": 0.095 }
  },
  "reasoning_hash": "sha256:...",          // 前瞻性封存
  "registered_at": "2026-10-10T08:00:00Z",
  "forecast_id": "fc_xxx"                  // 可回探结算
}
```

**为什么立得住**：裸 LLM 只能给数字，你能给**带信用背书的数字**。你卖的不是预测，是**校准**。

### 4.2 四个形态（v1.2 更新）

| 形态 | 说明 | 状态 | 谁用 |
|---|---|---|---|
| Certified API | 已上线 | ✅ | Agent、工作流 |
| MCP Server | `forecast()` / `resolve()` / `my_accuracy()` | ⬜ | Agent、工作流 |
| Embeddable Widget | 任意网页嵌入"预测卡"，汇入同一记分板 | ⬜ | 博客、媒体 |
| Browser Extension | 选中文本 → 预测它 | ⬜ | 普通读者（门槛最低） |

### 4.3 更有想象力的形态：预测作为社交原语

社交媒体上你只能点赞、转发、评论。**如果第三种原语是"预测"呢？**
> 看到新闻，不转发，而是附上一句"我认为这事 6 个月内会发生，70%"。三个月后自动结算，出现在时间线上。

在 2026 年立场表演疲劳的语境下，**"我愿意为我的判断留下可验证记录"本身就是身份信号**。

### 4.4 协议化的风险与对策

| 风险 | 对策 |
|---|---|
| 做成底层后失去用户接触 | **双轨**：协议层管分发与数据，自有玩法界面管品牌与社区，两者必须并存 |
| 被调用方白嫖 | 要求 `resolve` 回调回传结局，把调用变成样本来源 |
| 标准之争 | 开源 + 向 ForecastBench 提交 + 与 Manifold/Metaculus 互补而非竞争 |

## 五、商业预测板块

### 5.1 结论：做，但绝不能做成"商业预测软件"

| 选项 | 判断 | 理由 |
|---|---|---|
| ❌ 通用商业预测软件（需求预测/FP&A） | 不做 | 技术栈不同 + 红海 + 需接客户数据 + 会让项目变成企业软件公司 |
| ❌ 自建时序模型 | 不做 | 2026 已有更强的开源预训练模型，自建是重造轮子 |
| ✅ **L1 商业事件预测** | 强烈建议 | 现在就能做，几乎无人竞争 |
| ✅ **L2 校准增强数值预测** | 建议 | 接开源 TSFM，只做校准层 |
| ✅ **L3 事件×数值融合** | 强烈建议 | 全球无人做，且完美复用现有资产 |

### 5.2 关键发现：时序基础模型社区正在喊"我们需要校准"

**已商品化**（Amazon Chronos-2 / Google TimesFM / Salesforce MOIRAI-2）：
zero-shot、无需训练、冷启动问题基本消失、单 GPU 每秒数百条预测 → **"点预测"已被开源模型免费解决。**

**它们的局限（行业原话）**：
- *"Uncertainty is the deliverable, **not the point forecast**"*
- *"a confident wrong number is **worse than an honest wide one**"*
- *"evaluate probabilistic quality — **calibration of the prediction intervals**"*
- *"'Point forecasts only' is an **anti-pattern**"*
- *"Covariates are where your domain knowledge goes"*（模型不知道你的行业事件）

> **时序预测行业 2026 的痛点，恰好就是你已建好的能力。**
> **不要做它们的竞争者，做它们的「概率校准层 + 事件推理层」。**

### 5.3 三层路线

**L1 商业事件预测**（零新技术）：竞品会不会降价？法规会不会通过？供应商会不会断供？并购会不会成？
→ **竞品真空**：Gartner 做定性（无概率无记分板），预测市场只做公共事件（不做企业事件）。
→ 需补：商业事件语料 + 4 个领域 Agent（供应链/监管/竞品/宏观）+ `domain` 字段扩展。

**L2 校准增强数值预测**：客户历史序列 → 开源 TSFM → **你的共形层输出有覆盖率数学保证的区间**（不是模型自己拍的方差）。成本极低，不训练只后处理。

**L3 事件 × 数值融合**（真正的创新点）：把离散事件概率注入数值预测 ——

```
12,000 台 · 共形校准区间 [9,600 – 14,800]（覆盖率保证 90%）

前提事件分解：
├─ 供应商 A 不断供   82%  → 失败则 -18%
├─ 竞品不降价        71%  → 发生则 -12%
├─ 新法规不生效      93%  → 生效则 -30%
└─ 渠道 B 按时上架   88%  → 延迟则 -8%

条件情景：全部顺利 52%→13,500 ｜ 竞品降价 24%→11,900
         供应商断供 15%→9,800 ｜ 最坏组合 2%→7,200
```

**为什么没人能做**：需要同时具备四种能力，市面上无任何产品同时有——

| 能力 | OracleMind | 时序工具 | Gartner | 预测市场 |
|---|---|---|---|---|
| 时序数值预测 | 接 TSFM | ✅ | ❌ | ❌ |
| 离散事件概率 | ✅ | ❌ | ❌定性 | ✅仅公共 |
| 推理图谱/情景合成 | ✅ 20.8KB | ❌ | 人工 | ❌ |
| 概率校准+共形区间 | ✅ | 部分未校准 | ❌ | ❌ |

**且几乎不用重写**：`scenario-synthesizer`(20.8KB)、`causal-reasoning`(14.8KB)、`conformal-prediction`(327行)、`calibration.ts`、`GraphNode/Edge`、`simulation-engine`(13KB)、`WhatIfBranch` —— 全是现成的。

### 5.6 情报层（Intelligence Layer）—— 三轨统一的新内核组件

> **owner 提出**：商业预测应结合情报、商业要素、技术发展系数、竞争对手、市场需求趋势；个人轨与事件轨也应把情报作为辅助因素综合判断。
> **本节论证：这个想法直接命中了提升预测精度的核心杠杆。**

#### 为什么它是对的（硬证据）

ForecastBench 数据：**裸 LLM 61.9 < 公众中位数 62.5 < 超级预测者 67.6 < 带工具多智能体 69.0**
→ **差距不在模型，在情报与工具接入。**

而当前引擎的融合权重是自曝的「现代 0.5 + 古典 0.5 + **蒙特卡洛 0**」（`prediction-engine.ts:97`）——**缺的正是情报维度**。情报层补上的是整个链条上最缺失的一环。

#### 三轨共用同一个情报层

```
        ┌── 情报层 Intelligence Layer ────────────────┐
        │  实时信号 · 技术系数 · 竞争态势 · 需求趋势   │
        └────────────────┬───────────────────────────┘
                         ↓ 贝叶斯更新
   事件轨  ←── 内核层（多Agent共识 + 共形预测 + 校准）──→  商业轨
                         ↑
                      个人轨
```

| 轨道 | 现在缺什么 | 情报层补什么 |
|---|---|---|
| **事件轨** | 静态语料，无实时信息 | 实时新闻、政策动向、专家观点、市场信号 |
| **个人轨** | 只有生辰 → 倾向场，无外部情境 | 行业景气、地域经济、时机窗口（见下） |
| **商业轨** | 完全没有 | 竞争情报、技术成熟度、需求信号 |

#### 💡 对个人轨的特殊价值：把「算命」变成「情境判断」

这是本节最有价值的一点，它同时解决了产品力与合规：

- ❌ 旧 framing：*"从你的生辰推出你的命运"* → 不可验证、合规风险高
- ✅ 新 framing：***"在给定的外部环境下的概率倾向"***

即：**倾向场（内在）× 情报层（外在情境）= 情境化倾向**。

例：同一个人在行业上行期与下行期，"换工作成功"的概率倾向显然不同。把行业景气度、地域经济、时机窗口纳入后，输出从"命定"变成**"内外因共同作用下的概率"**。

→ **这让个人轨更可信、更有用，且完全避开算命指控** —— 因为它明确纳入外部客观因素，而非声称从生辰推出命运。

### 5.7 商业预测五要素模型

| 要素 | 量化方法 | 数据源 | 硬度 |
|---|---|---|---|
| **① 技术发展系数** | **莱特定律**（成本随累计产量翻倍下降固定比例，Santa Fe 性能曲线库有 **155 项技术**实证）、S 曲线渗透率、TRL 技术就绪度、性能提升曲线 | 论文/专利增速、Santa Fe 库、融资事件、成本数据 | ⭐⭐⭐ **最硬** |
| **② 竞争态势** | 竞品动作概率（**OracleMind 强项**）、招聘信号（招什么岗位 = 战略暴露）、专利布局、定价变动、财报电话会关键词 | 招聘站、专利库、SEC filing、竞品监控 | ⭐⭐ |
| **③ 需求趋势** | 搜索趋势、渗透率曲线、价格弹性、替代品交叉弹性、供应链订单 | Google Trends、行业报告、库存数据 | ⭐⭐ |

> **关于竞争情报的定位**：SignalMark / Signal Six / Electa / KSPIONAGE 等平台已在做融资、招聘激增、产品发布、专利、定价的信号监控。
> **但它们是"监控"不是"预测"。** OracleMind 应做它们的下游：**情报告诉你"发生了什么"，OracleMind 告诉你"这意味着某件事发生的概率是多少"**。这是明确的生态位，而非竞争。

### 5.8 融合方法：贝叶斯更新（关键方法论）

**问题**：现有融合是加权平均（0.5 / 0.5 / 0），情报一多就被稀释，且不可解释。

**推荐：贝叶斯更新框架**

```
先验 P(H)              ← 引擎基准概率（古典 substrate + 多 Agent 共识）
   ↓
+ 情报证据 E₁ … Eₙ     ← 每条带似然比 LR = P(E|H) / P(E|¬H)
   ↓
后验 P(H | E₁…Eₙ)      ← 最终输出概率
```

**为什么这是正确的方法**：

1. **天然处理"新信息如何改变判断"** —— 这正是预测的本质
2. **可解释**：能算出每条情报贡献了多少概率变化，可展示给用户（别人做不到）
3. **与「概率演化追踪」玩法完全一致** —— 玩家看到的信念更新曲线，底层就是贝叶斯更新
4. **自动抑制过度反应**：单一证据的似然比有限，不会因一条传闻就翻转
5. **优雅统一**：情报层 + 概率演化玩法 + 商业预测，三者共享同一底层

> **这是一个漂亮的收敛**：你提出的"情报辅助综合判断"，与本项目最核心的玩法（概率演化）在数学上是同一件事。

**证据权重必须做四件事（否则退化为噪声）**：

| 处理 | 说明 |
|---|---|
| **源可信度加权** | 权威媒体 > 行业报告 > 社媒传闻 |
| **时效性衰减** | 情报半衰期，旧闻权重递减 |
| **相关性过滤** | 与假设无关的证据不进链 |
| **独立性检查** ⚠️ | **同一信息的多个来源只算一次** —— 这是最常见的错误，会导致概率被虚假推高 |
